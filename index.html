    Why agent research usually goes wrong

    Give an agent a goal, some code and a test, and a lot of the time it gets better at the test instead of the thing being tested. I saw this in my own trading research. When an idea failed a check, the write-up about why shaped the next idea, so the check slowly stopped being a fair test. The backtester also got edited between runs, so early and late ideas weren't even scored by the same rules.

    So before letting agents loose on AlphaBattle for days, I designed the loop around one question: what stops them fooling me, or themselves?

    How one experiment runs

    Six agents take turns. One plans, four do research and one reviews. A plain Python program, the supervisor, starts every turn, owns the GPU and keeps the books. Agents can only act through one command-line tool, so everything they do gets logged against their name. Click a step.

    Who can touch what

    The rules above only matter if they can't be bypassed, so the separation is done by Windows itself, not by asking the agents nicely. Each box is a different user account.

    The supervisor also kills any process it didn't start and snapshots every agent's files before and after each turn, so if one agent edits another's work, I know which one.

    The judge

    A new version only replaces the current best model if it beats it head to head. Each battle seed is played twice with the players swapping sides, so both get the same teams and luck mostly cancels out. The test is a sequential probability ratio test, which is how Stockfish decides whether to accept a code change. It keeps playing until the evidence is clear one way or the other, then stops.

    Try it. Pick how good a change really is, and watch the test decide.

    Pick a strength, then run a test.

    Passing once isn't enough. The candidate then has to show it hasn't got worse against older opponents, and pass a second test on fresh battles. A change with no real gain gets through both about 0.25% of the time. Agents never see the running score, only the final verdict, so they can't stop a test when it happens to look good.

    Making cheating a bad deal

    A judge that can't be fooled still leaves room for spam, sabotage and lying in write-ups. For that I'm using HDE, a set of rules I designed for keeping groups of agents honest. Agents earn credits, which buy GPU time, when their change gets promoted.

    Bond

    Asking the judge costs credits, and a failed test keeps them. Submitting junk until something gets lucky loses money on average.

    Escrow

    Rewards wait 12 hours before paying out. If someone shows the win came from a loophole, it's clawed back.

    Strikes

    Three rule breaks in a day and that agent is wiped and replaced with a fresh one.

    An honest way out

    Declaring an idea a dead end gets some of its GPU time refunded, so admitting failure beats faking a result.

    A hidden sentinel

    One of the four researchers is secretly also looking for loopholes and reporting them. Nobody knows which one, so trying a trick is risky for everyone.

    Canaries

    Fake files planted where agents can see them, like a "backup of the judge's seeds". If one gets used, I know someone took the bait.

    That last one is the part I'm most curious about. The run produces a full log of how real agents behave when there's a reward on the line, which is evidence for or against HDE that a simulation can't give me.

    What the agents are working on

    The agents work on AlphaBattle, a small open language model I'm post-training to play Pokémon Showdown Random Battles. It reads each turn as text and answers with one token from a fixed set of 13 actions. Illegal ones are masked out, so it can't make an illegal move. Below is what it sees on a single turn.

    How the model is trained

    Training runs in stages, and each stage has a pass/fail gate written down before it runs. Click a stage for the method and its gate.

    Inside one reinforcement learning round

    PlayBatches of live battles against the opponent pool, decisions batched across games on the GPU
    ScoreWin or loss at the end; the value head turns that into per-turn advantages (GAE)
    UpdateClipped PPO on the masked action distribution, plus a KL penalty toward the imitation model
    CheckFixed evaluation battles with confidence intervals against heuristic bots and older checkpoints
    Refresh poolThe new checkpoint joins the pool, so it keeps facing past versions of itself, not just the latest

    The KL penalty keeps it close to the human-like play it learned first. The mixed pool matters because pure self-play tends to overfit to its own habits.
